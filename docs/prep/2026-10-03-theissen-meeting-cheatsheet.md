# Cheat sheet — 10/03 跟 Theissen 聊新 project (20 min)

**定位:** 只是一个 brief 的想法介绍。我讲 ~5 分钟, 剩下听他说。细节一律 "这个我回头再研究"。

---

## 1. 故事线 (按顺序讲)

**① 我觉得有意思的问题**
- 上次您提的: 测比观测基线更长的 rotation period。我想接着做这个。
- 为什么有意思: 老的、转得慢的 K/M dwarf, 自转周期就是年龄的钟。但它们很多 P > 13 天, 正好是 TESS 最难测的区间。

**② 我发现 light curve 有两个问题**
- **Scattered light:** TESS 轨道 13.7 天, 地球/月亮的杂散光跟着轨道周期变, 跟慢转星的信号叠在同一个时间尺度上。
- **Contamination:** 像素 21"/px (Kepler 是 4"/px), 一个 aperture 里常混着邻星。这是您 9/19 提醒我的那点。
- 关键: 做成 light curve 时, 每一帧被压成**一个数**。杂散光、目标星、邻星三样混在这一个数里, 之后就很难再分开。

**③ 所以想直接用 image**
- TESS 实际拍的是一段像素"小视频" (FFI cutout)。在像素里这三样长得不一样:

| 来源 | 在像素里的样子 |
|---|---|
| 杂散光 / 指向抖动 | 很多相隔很远的像素一起变 |
| 目标星 | 一个 PSF 形状的光斑, 固定在目标位置 |
| 邻星 | 同样的光斑, 但在别的位置 |

- 而且每一帧地球、月亮在相机的什么方向、多远, 是**已知**的 (公开的工程数据, `tessvectors`), 可以直接告诉模型。

**④ 我设想的 pipeline (三句话, 不展开)**
1. **输入:** 目标星周围的像素小视频 + 每一帧地球/月亮的位置。
2. **训练 (不需要标签):** 把视频遮掉一部分让模型去猜。要猜得准, 它就得自己学会哪些变化来自望远镜、哪些来自星。
3. **输出:** 去掉杂散光后的干净 light curve → 用普通的 Lomb–Scargle 量周期; 外加一张图, 指出是视野里哪颗星在转。

- **怎么验证:** 不用 TARS 当真值 (暑期的教训: 它既是标签又是标杆)。用独立来源的周期 (Kepler 场、ZTF), 再加"往真实像素里注入假信号, 看能不能找回来"。

**⑤ 收尾 (一定要说)**
> 我还没有深入调研过。像素层面已经有人做过线性的方法 (`unpopular`), Hattori+2025 的长周期结果就是基于它的。我回头想更系统地查别人在类似任务上的经验。您要是知道相关的工作, 或者觉得哪里不对, 请尽管说。

## 3. 被问到细节时

以下都答 **"这个我还没定, 回头研究完跟您汇报"**:
- 模型具体用什么结构
- 数据做多大、选哪些 sector
- 跟现有方法 (`unpopular` 等) 具体怎么比
- 真值星表在 TESS 里的覆盖情况

**主动说的一个风险:** 星在 TESS 里只占几个像素, 像素可能并不比现有线性方法多出多少信息。如果是这样, "像素帮不上忙" 本身也是一个可以报告的结论。

**两句别说错:**
- 别说 "现有 pipeline 不看像素" — SPOC、`unpopular`、TGLC 都在像素层面工作。空白是: 没人在像素上用**学习型模型**做 rotation。
- "杂散光在空间上平滑" 没有直接出处 → 只当问题问 (§2 第 1 条), 不当事实讲。
